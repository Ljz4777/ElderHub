# ElderHub 颐养中心 —— 餐饮管理模块 变更说明

> 文档目的：说明「添加餐饮管理功能」需要改哪里、怎么改、为什么这么改，供前端联调与团队评审使用。
> 配套文档：`13-餐饮管理接口文档.md`（接口明细）；`sql/16~18`（建表脚本）。

---

## 1. 变更背景（为什么现在做）

- 前端页面已上线：菜单「餐饮管理」下已有「餐饮管理」「客户偏好」两个页面。
- 但页面点击后显示 **「模块建设中」**：提示后端 Food / Meal / CustomerPreference 服务层已就绪、Controller 尚未开发。
- 团队负责人（吕俊哲）在群内指出「餐饮管理这一块还没有开发」，要求补齐缺失功能。

**结论**：本次变更 = 补齐餐饮模块**后端接口层（Controller + Service 业务方法）**，使前端页面可接入真实数据。

## 3. 具体改动（怎么改）

### 3.1 新增后端文件（9 个 Java 文件）

| 模块 | Service 接口 | Service 实现 | Controller |
| --- | --- | --- | --- |
| 食品信息 | `service/FoodService.java` | `service/impl/FoodServiceImpl.java` | `controller/FoodController.java` |
| 膳食日历 | `service/MealService.java` | `service/impl/MealServiceImpl.java` | `controller/MealController.java` |

**统一接入路径**（基础路径 `/admin`，全部经 JWT 拦截器校验登录）：

| 模块 | 路径 | 接口 |
| --- | --- | --- |
| 食品信息 | `/admin/food` | `GET /list`（分页/名称模糊/分类/清真筛选）、`GET /{id}`、`POST /save`、`PUT /update`、`DELETE /remove/{id}` |

### 3.2 数据库（无需改动，已有建表脚本）

- `sql/16_biz_food.sql`：食品信息表
- `sql/17_biz_customer_preference.sql`：客户饮食喜好表
- `sql/18_biz_meal.sql`：膳食日历表

> 注意：三张表需在 `elderhub` 库中**已执行**建表，否则接口查询会报表不存在。

## 4. 为什么这么改（设计依据）

### 4.1 沿用项目既有架构规范，不引入新东西
- 统一响应 `Result<T>`、分页 `IPage<Entity>`、JWT 认证、逻辑删除手动置 `is_deleted`，全部复用现有模块（如 `NurseContent`）的既有写法，保持全项目风格一致，降低评审/维护成本。

### 4.2 不重复造轮子：entity / mapper / 建表脚本已存在
- 三张表的实体与 Mapper 已由代码生成器生成，无需改动，只在其上补业务方法与接口层。

### 4.3 删除语义由表结构决定（关键差异）
- `food` 表**没有** `is_deleted` 字段 → 采用**物理删除**（`deleteById`）。
- `meal`、`customer_preference` 表**有** `is_deleted` 字段 → 采用**逻辑删除**（置 `is_deleted=1`），查询默认过滤已删记录。
- 这样严格对齐数据库设计，避免对不存在的字段做逻辑删除。

### 4.4 字段命名用 snake_case，与现有配置对齐
- `application.yml` 中 `map-underscore-to-camel-case: false`，实体字段名与数据库列名一致，因此接口 JSON 字段为 `food_name`、`is_halal`、`week_day`、`customer_id` 等。前端对接需按此命名。

### 4.5 权限按角色划分，暂只开放管理员
- 三套接口均挂在 `/admin` 前缀下，仅管理员可访问，与设计文档 4.5 节「膳食管理（可选扩展）」定位一致。
- 健康管家（`/nurse`）暂不涉及餐饮操作，如需开放可在后续迭代追加并做客户归属校验。

### 4.6 不改动现有表结构与既有模块
- 本次只**新增**文件，未修改任何既有实体、Mapper、Service 或 Controller，避免影响入住、护理等其他已上线模块。

---

## 5. 联调与验收要点

1. **建表**：确认 `sql/16/17/18` 已在 `elderhub` 库执行。
2. **认证**：所有接口需登录后带 `Authorization: Bearer <token>`。
3. **前端接入**：按 `13-餐饮管理接口文档.md` 的路径与 snake_case 字段对接「餐饮管理」「客户偏好」页面。
4. **删除语义**：`food` 删除后不可恢复（物理）；`meal`/`customer_preference` 删除后可查询仅隐藏（逻辑）。

---

## 6. 已知问题（与本模块无关，需另修）

- 项目当前存在 **Ambiguous mapping（请求映射歧义）** 启动报错：`NurseRecordButlerController` 与 `NurseDailyController` 重复定义了 `POST /nurse/nurse-record/save`，导致 Spring 无法启动。
- 该问题属于健康管家模块，**不影响本餐饮模块代码的正确性**，但会阻塞整个应用启动，需由负责该模块的同事处理（删除重复控制器或改其一路径）。
