# 餐饮管理模块接口文档

## 模块概述

餐饮管理模块包含三个子功能：**食品信息管理**、**膳食日历管理**、**客户饮食偏好管理**。

- 食品信息：维护菜品库（名称、分类、价格、是否清真、图片）。
- 膳食日历：按星期 + 餐次（早/午/晚）排布每周菜单，关联食品。
- 客户偏好：维护每位客户的饮食喜好、忌口注意事项。

**权限说明：** 本模块接口均为管理员接口，基础路径统一带 `/admin` 前缀。全部接口需携带 JWT（请求头 `Authorization: Bearer <token>`）。

**通用响应格式：** 所有接口返回 `Result<T>`：

```json
{
  "code": 200,
  "message": "success",
  "data": { }
}
```

- `code=200` 表示成功；`code=500` 表示失败（`message` 为错误信息）。
- 分页接口 `data` 为 MyBatis-Plus `IPage` 对象：`{ "records": [...], "total": 总条数, "size": 每页条数, "current": 当前页, "pages": 总页数 }`。

# 一、食品信息管理

**基础路径：** `/admin/food`

## 数据模型（Food 实体 / food 表）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Integer | 主键ID |
| food_name | String | 食品名称 |
| food_type | String | 食品分类 |
| price | BigDecimal | 食品价格（单位：元，两位小数） |
| is_halal | Integer | 是否清真（0=否 1=是，默认0） |
| food_img | String | 食品图片路径 |

> 说明：`food` 表**没有** `is_deleted` 字段，删除操作为**物理删除**，删除后不可恢复。

---

## 1. 分页查询食品

- **方法：** `GET`
- **路径：** `/admin/food/list`

### 请求参数（Query）

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| pageNum | Integer | 否 | 1 | 页码 |
| pageSize | Integer | 否 | 10 | 每页条数 |
| foodName | String | 否 | - | 食品名称模糊查询 |
| foodType | String | 否 | - | 食品分类筛选 |
| isHalal | Integer | 否 | - | 是否清真筛选（0/1） |

### 请求示例

```
GET /admin/food/list?pageNum=1&pageSize=10&foodName=红烧&isHalal=0
```

### 响应 data

```json
{
  "records": [
    { "id": 1, "food_name": "红烧肉", "food_type": "荤菜", "price": 18.00, "is_halal": 0, "food_img": "/img/food/001.png" }
  ],
  "total": 1,
  "size": 10,
  "current": 1,
  "pages": 1
}
```

---

## 2. 查询食品详情

- **方法：** `GET`
- **路径：** `/admin/food/{id}`

### 路径参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Integer | 食品ID |

### 响应 data

单个 `Food` 对象。

---

## 3. 新增食品

- **方法：** `POST`
- **路径：** `/admin/food/save`
- **Content-Type：** `application/json`

### 请求体

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| food_name | String | 是 | 食品名称 |
| food_type | String | 否 | 食品分类 |
| price | BigDecimal | 否 | 食品价格 |
| is_halal | Integer | 否 | 是否清真，默认0 |
| food_img | String | 否 | 食品图片路径 |

### 请求示例

```json
{
  "food_name": "清炒时蔬",
  "food_type": "素菜",
  "price": 8.50,
  "is_halal": 1,
  "food_img": "/img/food/002.png"
}
```

---

## 4. 修改食品

- **方法：** `PUT`
- **路径：** `/admin/food/update`
- **Content-Type：** `application/json`

### 请求体

传入完整 `Food` 对象（**必须包含 `id`**）。

---

## 5. 删除食品（物理删除）

- **方法：** `DELETE`
- **路径：** `/admin/food/remove/{id}`

### 路径参数

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Integer | 食品ID |

> 注意：`food` 表无逻辑删除字段，此操作为物理删除，数据不可恢复。

# 四、开发与联调注意事项

1. **请求前缀**：完整访问路径 = 服务上下文 + 接口路径，例如 `http://localhost:8080/ElderHub/admin/food/list`（context-path 见 `application.yml`）。
2. **认证**：所有接口需在请求头携带 `Authorization: Bearer <token>`，登录接口见 `01-登录认证接口文档.md`。
3. **字段命名**：接口 JSON 字段为 snake_case（与数据库列名一致），如 `food_name`、`is_halal`、`week_day`、`customer_id`，前端对接时按此命名。
4. **删除语义**：`food` 为物理删除；`meal`、`customer_preference` 为逻辑删除。
5. **建表脚本**：`sql/16_biz_food.sql`、`sql/17_biz_customer_preference.sql`、`sql/18_biz_meal.sql`。
