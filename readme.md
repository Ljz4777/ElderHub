# ElderHub 养老服务管理平台

## 项目简介

ElderHub 是一套面向养老院、社区养老中心等养老机构的**前后端分离养老服务管理系统**，后端基于 SpringBoot 开发，前端采用 Vue3 + Element Plus 开发，用于数字化管理院内老人基础档案、健康信息、护理服务、床位分配、人员账号权限等核心业务。

传统养老机构大多依靠纸质台账记录老人信息、护理记录、床位使用情况，存在查找慢、易丢失、统计困难等问题。本项目通过信息化手段，将养老机构日常业务线上化，实现老人档案统一管理、护理流程可追溯、床位状态实时监控、人员权限分级管控，减轻护理人员与管理人员的手工登记压力，提升养老机构运营管理效率。

本项目为小组协作开发项目，后端采用经典分层架构，搭配 MySQL 8.0 数据库；前后端完全分离，后端只负责提供 RESTful API 接口，前端负责页面渲染、表单交互、数据可视化展示。团队采用 GitHub Fork + Pull Request 模式进行代码管理与代码评审，保证代码质量。

## 功能模块

>
> 前后端协同实现以下模块，前端负责页面展示、表单录入、弹窗交互、图表展示；后端负责数据校验、业务处理、数据库读写、权限控制。

1. **用户管理模块**
   管理员、护工、老人账号管理，实现账号新增、启用 / 禁用、密码重置；基于角色实现权限控制，不同角色访问不同菜单与接口。

- 角色：超级管理员、机构管理员、护工、访客
- 前端页面：用户列表页、新增 / 编辑弹窗、角色分配弹窗
- 功能：账号新增、编辑、删除、状态启用禁用、密码重置、角色分配

2. **老人信息管理模块**
   老人基础档案录入、信息修改、档案查询；维护老人个人基础资料、家属联系人、紧急联系电话，支持档案条件检索与信息导出。

- 老人基础信息：姓名、年龄、身份证、住址、入院时间
- 家属信息：家属姓名、联系电话、与老人关系
- 前端功能：多条件模糊搜索、分页展示、表单录入、信息导出 Excel

3. **护理服务管理模块**
   护理项目登记维护、护理计划制定与排班、护理执行记录保存；记录每次护理内容、护理人员、护理时间，可追溯历史护理记录。

- 护理项目：洗头、擦身、喂药、康复训练等项目维护
- 护理计划：为老人制定周期性护理方案
- 护理记录：每次护理完成后填写记录，支持历史记录查询
- 前端页面：护理项目管理、护理计划表单、护理记录列表

4. **床位管理模块**
   床位信息维护、入住登记、退住办理；床位状态实时标记（空闲 / 占用 / 维修），方便分配床位。

- 床位信息：床位编号、房间号、楼层
- 入住：绑定老人，记录入住时间
- 退住：办理退住，释放床位，记录退住原因
- 前端可视化：床位看板，用不同颜色标识床位状态（空闲绿色、占用蓝色、维修红色）

5. **健康监测模块**
   老人体检记录录入、慢性病信息管理、健康档案维护；记录血压、血糖等健康指标，跟踪老人健康变化。

- 基础体检指标：血压、心率、血糖、体重
- 慢性病管理：高血压、糖尿病等病史登记
- 前端 ECharts 图表：展示老人健康指标随时间变化趋势图

6. **系统管理模块**
   数据字典管理、系统公告发布、操作日志记录；记录用户登录、数据修改等操作，实现操作留痕。

- 数据字典：统一维护系统下拉选项（护理类型、疾病类型等）
- 系统公告：发布院内通知公告
- 操作日志：记录用户登录、新增、修改、删除操作，方便审计追溯
- 前端页面：字典管理、公告发布编辑、操作日志查询页面

## 前端功能说明

1. **登录与权限路由**
   前端登录页面输入账号密码，请求后端接口校验；登录成功获取 token 保存，Pinia 存储用户信息与角色；**动态路由**，根据后端返回角色权限，动态生成侧边菜单，没有权限的页面无法访问。
2. **请求统一封装**
   Axios 统一拦截请求，自动在请求头携带 token；响应拦截统一处理后端返回码，统一弹窗提示成功 / 失败信息，token 过期自动跳转到登录页。
3. **通用后台布局**
   左侧侧边菜单、顶部导航栏、面包屑导航，页面内容区域；支持菜单折叠。
4. **通用组件封装**
   封装公共分页组件、搜索组件、弹窗组件，减少重复代码，提高开发效率。
5. **数据可视化**
   使用 ECharts 绘制床位使用率、老人数量统计、健康指标趋势图表，首页数据大盘展示。
6. **文件导出**
   支持老人档案、护理记录导出 Excel 文件，方便线下存档。

## 开发规范

### 后端规范

- 采用标准三层架构（Controller → Service → Mapper）开发，分层解耦，职责清晰
- 统一接口返回结果封装，前端统一处理成功 / 失败响应
- Git 提交规范：使用 `feat`、`fix`、`docs`、`refactor` 前缀描述提交内容，通过 Fork + Pull Request 进行代码评审后合并代码
    - feat：新增功能
    - fix：修复 bug
    - docs：文档修改
    - refactor：代码重构
- 命名规范：类名大驼峰，方法、变量小驼峰；数据库表名、字段名下划线命名
- 接口增加参数校验，防止非法参数传入；异常统一捕获处理，返回友好提示
- 代码注释：核心业务逻辑、复杂方法添加注释，便于团队成员阅读

### 前端规范

- 页面组件命名采用大驼峰；变量、方法小驼峰命名
- 页面按业务模块划分 views 文件夹，接口统一放在 api 文件夹管理
- 组件复用优先抽取公共组件，减少重复代码
- 表单增加前端基础校验，减轻后端压力
- Git 提交同样遵循规范，前端代码单独提交 PR

## 数据库设计说明

数据库名称：`elderhub_db`
采用分表设计，核心数据表：

1. `sys_user`：系统用户表（管理员、护工账号）
2. `sys_role`：角色表
3. `sys_user_role`：用户角色关联表
4. `elder`：老人基础信息表
5. `family_member`：老人家属信息表
6. `bed`：床位信息表
7. `nurse_item`：护理项目表
8. `nurse_plan`：护理计划表
9. `nurse_record`：护理执行记录表
10. `health_record`：老人健康体检记录表
11. `sys_dict`：数据字典表
12. `sys_notice`：系统公告表
13. `sys_oper_log`：系统操作日志表

>
> 所有表都包含创建时间、更新时间、创建人、更新人字段，用于数据追踪。

## 项目部署运行

### 环境准备

**后端**

- JDK 1.8
- MySQL 8.0
- Maven 3.6+
- IDEA 开发工具

**前端**

- Node.js 16+
- npm / yarn

### 运行步骤

#### 后端启动

1. 克隆项目到本地
2. 创建数据库 `elderhub_db`，执行 `sql` 目录下的建表脚本与基础数据脚本
3. 修改 `resources/application.yml` 文件，配置数据库 IP、端口、用户名、密码
4. IDEA 中 Maven 刷新，加载全部依赖包
5. 找到项目主启动类，运行 SpringBoot 项目
6. 启动成功后，访问 Knife4j 接口文档地址，查看并调试接口

#### 前端启动

1. 进入前端项目目录 `elderhub-admin-front`
2. 安装依赖
3. 修改 `src/api/request.js` 后端接口地址，指向后端服务地址
4. 本地开发启动
5. 浏览器访问前端页面，输入账号密码登录
6. 打包部署（生产环境）

```
npm run build
```

打包完成后 dist 文件夹可部署到 Nginx 静态服务器

## 项目亮点

1. **业务贴合养老场景**：围绕养老院真实业务流程设计，覆盖老人档案、护理、床位、健康监测核心业务。
2. **前后端分离架构**：前后端独立开发、并行开发，后端专注业务，前端专注交互与页面展示。
3. **权限分级管控**：多角色权限隔离，前端动态路由，不同岗位人员只能看到自己负责的数据，保障数据安全。
4. **操作留痕**：所有数据增删改操作记录日志，便于追溯。
5. **可视化大屏**：ECharts 实现床位、健康数据统计图表，直观展示机构运营状态。
6. **团队协作规范**：采用 Fork+PR 模式，代码提交前评审，降低代码冲突风险。
7. **接口文档自动生成**：集成 Knife4j，后端开发完成即可在线查看接口，方便前端对接。
